# 집 가 — 프론트엔드 화면 명세

> 프론트 담당자에게 넘기는 구현 문서. 이 문서만 보고 화면을 짤 수 있게 쓴다.
>
> 작성일: 2026-08-25 · React Native
>
> 설계 배경이 궁금하면 [설계 정리](집가_설계정리.md)와 [파장 흐름 설계](../docs/superpowers/specs/2026-08-25-파장흐름-design.md)를 본다.
> **미니게임 자체는 이 문서의 범위가 아니다.** 게임 개발자용 계약은 설계 정리 §4에 있다.

---

## 0. 먼저 알아야 할 것 세 가지

**1. 게임 중에는 네트워크가 없다.** 각자 폰에서 독립 실행하고 끝날 때 점수만 올린다. 게임 화면은 통신 상태를 신경 쓸 필요가 없다.

**2. 벌칙은 "카카오T가 열리고 방에서 나가는 것"이다.** 이 앱에서 제일 중요한 순간이므로 연출에 힘을 준다.

**3. 딥링크는 콜백이 없다.** 카카오T를 열어준 뒤 그 사람이 실제로 탔는지 알 방법이 없다. 그래서 "아직 안 갈래" 재입장이 반드시 있어야 한다.

---

## 1. 용어

| 용어 | 뜻 | 수명 |
|---|---|---|
| **방** (Room) | 술자리 하나. QR로 모인 인원의 단위 | TTL 2시간 |
| **세션** (Session) | 한 번 열리는 미니게임 3판 묶음 | 5분 내외 |
| **판** (Round) | 미니게임 1회 | `timeLimitSec` |

한 방 안에서 세션이 30~60분 주기로 여러 번 열린다.

---

## 2. 화면 목록

| ID | 화면 | 진입 |
|---|---|---|
| `S0` | 홈 | 앱 실행 |
| `S1` | 방 만들기 → QR 표시 | S0 |
| `S2` | QR 스캔 | S0 |
| `S3` | 로비 | S1 · S2 · 세션 종료 후 |
| `S4` | 게임 3개 공개 | S3에서 방장이 시작 |
| `S5` | 카운트다운 | S4 · 판 결과 후 |
| `S6` | 게임 호스트 | S5 |
| `S7` | 판 결과 | S6 |
| `S8` | 세션 종합 결과 | 3판째 S7 이후 |
| `S9` | 벌칙 (집 가) | S8, 평균 < 40 |
| `S10` | 귀가 완료 | S9 · S3의 "집에 갈래" |
| `S11` | 다음 세션 대기 | 세션 도중 입장·재입장 |

## 4. 화면별 명세

### S0 — 홈

| 요소 | 조건 |
|---|---|
| 방 만들기 버튼 | 항상 |
| QR 스캔 버튼 | 항상 |
| **"아직 안 갈래"** 버튼 | 로컬에 방 코드가 저장돼 있을 때만 |

"아직 안 갈래"를 누르면 저장된 방 코드로 재입장을 시도한다.

- 방이 살아있음 → S3 (세션 진행 중이면 S11)
- 방이 이미 소멸 → "방이 사라졌어요" 안내 후 로컬 코드 삭제, S0 유지

---

### S1 — 방 만들기 → QR 표시

- QR 코드 크게. 딥링크 `jipga://room/{코드}`를 인코딩
- **방 코드를 텍스트로도 병기.** QR이 안 찍힐 때의 유일한 대안이다
- 방장 본인은 자동으로 참가자 1번
- 입장하는 사람이 실시간으로 카운트되는 표시 (Supabase Presence)
- "다 들어왔어요" → S3

---

### S2 — QR 스캔

- 카메라 권한 요청 처리 필요
- 스캔 성공 → 바로 입장 → S3
- **코드 직접 입력 폴백을 반드시 넣는다.** 어두운 술집에서 스캔이 실패하는 경우가 흔하다

---

### S3 — 로비

이 앱에서 사람들이 가장 오래 머무는 화면이다.

| 요소 | 비고 |
|---|---|
| 참가자 목록 | 실시간. 방장 표시 |
| **다음 세션까지 남은 시간** | 없으면 사람들이 폰을 계속 확인한다 |
| "게임할 시간!" 배지 | 주기 도달 시 |
| 시작 버튼 | **방장에게만.** 주기 도달 전에도 누를 수 있음 |
| 주기 설정 (30 / 45 / 60분) | **방장에게만** |
| **"집에 갈래"** 버튼 | 전원. 세션 사이에만 노출. `leave_room()` → 응답 확인 → 딥링크 → `S10` |

> ⚠️ **게임 선택 UI는 없다.** 방장은 "시작"만 누르고 무엇을 할지는 아무도 모른다. 방장이 고르게 하면 자기가 잘하는 게임을 고르기 때문이다.

> ⚠️ 참가자가 2명 미만이면 시작 버튼을 비활성화한다.

---

### S4 — 게임 3개 공개

세션의 오프닝 연출이다.

- 서버가 발급한 세션 시드에서 게임 3개가 추첨된다 (중복 없음)
- 슬롯머신처럼 돌다가 하나씩 확정되는 연출을 권장
- 각 게임의 `emoji` · `name` · `desc` 표시
- 전원 화면에서 동시에 재생 → S5

---

### S5 — 카운트다운

- 서버가 지정한 시작 시각에 맞춰 3 · 2 · 1
- 폰 시계가 아니라 **서버 시각 기준**으로 맞춘다. 안 그러면 출발선이 어긋난다
- 이번 판의 게임 이름과 제한시간을 같이 노출

---

### S6 — 게임 호스트

미니게임 모듈을 띄우는 껍데기다. 게임 내부는 다른 개발자 담당.

**모듈에 넘기는 값**

```
seed          : number
timeLimitSec  : number
```

**모듈이 돌려주는 값**

```
normalizedScore : number   // 0~100, 높을수록 좋음 — 판정에 쓰이는 유일한 값
score           : number   // 원점수, 화면 표시 전용
tiebreakMs      : number   // 걸린 시간(ms)
finished        : boolean
```

호스트가 할 일

- 남은 시간 표시 (게임 모듈이 자체 표시하지 않는 경우 대비)
- 모듈 반환값을 서버로 제출
- **제한시간이 지나도 모듈이 반환하지 않으면** 강제 종료하고 `finished: false`, 그때까지 값으로 제출
- 뒤로가기 / 앱 이탈 시 미제출 → 서버가 0점 처리

---

### S7 — 판 결과

- **그 판의 순위만** 보여준다
- **누적 평균은 절대 노출하지 않는다.** 3판째까지 긴장을 유지하기 위함이다
- `score` 원점수로 표시 ("18/20문제"). `normalizedScore`는 안 보여줘도 된다
- 1·2판 후 → S5 (다음 판) · 3판 후 → S8

---

### S8 — 세션 종합 결과

3판 평균이 처음 공개되는 순간이다.

- 3판 평균 `normalizedScore` 순으로 최종 순위
- 동점이면 `tiebreakMs` 오름차순
- **40점 미달자를 강조 표시**
- 통과자 화면에도 누가 걸렸는지 같이 보여준다 — 벌칙은 본인만 보면 재미가 없다

분기

- 본인이 40 이상 → 대기 화면 → S3
- 본인이 40 미만 → S9

---

### S9 — 벌칙 (집 가)

이 앱의 하이라이트다.

```
    end_session 응답에서 penalized: true 확인
        ▼
    "집 가" 대문짝만하게
        ▼
    3 · 2 · 1 카운트다운
        ▼
    카카오T 딥링크 실행
        ▼
        S10
```

> **방 제거는 이미 끝나 있다.** `end_session` RPC가 판정과 강퇴를 한 트랜잭션에서 처리하므로 클라이언트가 따로 제거를 호출하지 않는다. 응답의 `penalized: true`를 보고 연출만 재생하면 된다.

> ⚠️ **`S3`의 "집에 갈래"는 다르다.** 그쪽은 클라이언트가 `leave_room()`을 직접 부르므로 **순서를 지켜야 한다** — 응답을 받은 뒤에 딥링크를 연다. 딥링크를 먼저 쏘면 앱이 백그라운드로 내려가면서 요청이 유실된다.

카카오T 실행

| 플랫폼 | 값 |
|---|---|
| Android 패키지 | `com.kakao.taxi` |
| iOS App Store ID | `981110422` |

미설치 시 스토어로 폴백. 공식 API가 아니므로 **출시 전 실기기 검증 필수.**

---

### S10 — 귀가 완료

카카오T에서 앱으로 돌아왔을 때 보이는 화면이다.

- 방 코드를 **로컬에 저장한다.** S0의 "아직 안 갈래"가 이걸 쓴다
- "조심히 가세요" 정도의 마무리
- "아직 안 갈래" 버튼을 여기에도 둔다 (실수로 눌렀거나 안 타는 경우)

---

### S11 — 다음 세션 대기

세션이 진행 중일 때 들어온 사람(신규 입장 · 재입장 모두)이 보는 화면이다.

진행 중인 세션에는 끼지 않는다. 게임 3개와 시드가 이미 배포됐고 판이 돌아가는 중이기 때문이다.

- "다음 게임부터 참여할 수 있어요"
- 현재 몇 판째인지 정도만 표시. 관전 기능은 넣지 않는다
- 세션 종료 → S3

---

## 5. 문구 체계

어미 하나로 두 경로가 갈린다. **바꾸지 말 것.**

| 상황 | 문구 | 말하는 주체 |
|---|---|---|
| 벌칙 (타의) | **집 가** | 앱이 나에게 |
| 자발 귀가 (자의) | **집에 갈래** | 내가 앱에게 |
| 재입장 (자의) | **아직 안 갈래** | 내가 앱에게 |

"집 가"는 앱 이름이자 벌칙 대사다. 자발적 귀가에까지 같은 문구를 쓰면 무게가 희석된다. 자발적인 두 버튼은 `-ㄹ래`로 짝을 이루고 방향만 반대다.

## 6. 상태 분기 요약

| 화면 | 방장 | 일반 참가자 |
|---|---|---|
| S1 | QR 표시 · 인원 확인 | — |
| S3 | 시작 버튼 · 주기 설정 | 대기만 |
| S4~S8 | 동일 | 동일 |
| S9 | **동일 — 방장도 벌칙 예외 없음** | 동일 |

**방장이 나가면** 남은 사람 중 **가장 먼저 입장한 사람**이 자동 승계한다. 승계 사실을 새 방장에게 알린다. 재입장해도 방장은 돌려받지 않는다.

## 7. 엣지 케이스 체크리스트

- [ ] 게임 도중 앱 이탈 → 미제출 → 0점 → 평균 하락 → 대체로 벌칙. 별도 처리 없음
- [ ] 네트워크 순단으로 튕긴 사람 → S0의 "아직 안 갈래"로 복귀 가능
- [ ] 방장이 벌칙으로 나감 → 승계 후 남은 사람이 계속 진행
- [ ] 전원이 40 미만 → 전원 강퇴 → 인원 0 → **방 삭제.** 재입장 불가, 새로 파야 함
- [ ] 세션 도중 QR 스캔 입장 → S11
- [ ] 방 TTL 2시간 만료 후 재입장 시도 → "방이 사라졌어요"
- [ ] 카카오T 미설치 → 스토어 폴백
- [ ] QR 스캔 실패 → 코드 직접 입력 폴백
- [ ] 폰 절전 후 복귀 → Presence 재연결 처리. **Presence가 끊겨도 방은 살아있다** (TTL 기준)
- [ ] 참가자 2명 미만 → 시작 버튼 비활성화

---

## 8. 아직 안 정해진 것

프론트 작업 전에 확정이 필요한 항목.

- **디자인 톤** — 네온·다크 vs 밝고 귀여운. 미정
- **세션당 판수** — 현재 3판. 하드코딩하지 말고 상수로 뺄 것
- **세션 최소 인원** — 2명으로 제안, 미확정
- **누적 통계 / 역대 랭킹** — 현 설계에는 없음. 방이 소멸하면 기록도 사라진다
